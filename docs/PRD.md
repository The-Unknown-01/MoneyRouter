# 当前实现约定（2026-10-08）

采用手机优先 Web：Go 模板 + HTMX + daisyUI + ECharts，浏览器只访问 Go，Python 通过内部 HTTP/JSON 提供五类 Agent、账单清洗和答疑。Python Pydantic 模型与语义为标准；确认画像、本月实况、方案和复盘须显式用户确认。未知信息保持 null，整数分计算，转账排除收支。金融信息作为方案依据，不增加独立必经步骤。目标收益不作为保证或预测。

用户路径：登录 → 画像确认 → 账本预览/录入 → 本月核对确认 → 方案生成/修改/确认 → 可选答疑与复盘。复盘只选择已有落定记录月份，反馈进入下次方案输入。输入变化后原方案标为需更新；历史版本仍可回看。局部更新避免普通操作整页刷新。账号、会话和账本归 Go；Agent 检查点和业务产物归 Python。

运维和验收见 WEB_OPERATIONS.md、WEB_ACCEPTANCE_2026-10-08.md。以下保留产品初始目标。

# 主要目标：
资产保值。根据不同的风险承受能力进行分层，在资产积累的部分进行恰当的配置，实现适当的财富增值。
最终实现：保障基本开支，促进财富积累和健康理财。

# 功能：
1、分配必要的生活开支：基本生活成本、娱乐、教育
2、提供理财建议：风险预备金、保守储蓄、激进财富增值
承担一定的风险，允许短期亏损，预期年化大于3%

# 流程
## 1、前馈
问卷 - 判断算法
使用agent获取用户基本画像。
输入：账单等资料+用户回答问题
成果：获取用户收入情况、消费习惯、风险承受能力
## 2、提供方案
方案生成流程：
分析用户以往的消费习惯，结合用户画像，根据最新的世界新闻、金融情况，生成方案
成果：
1、开支额度分配、理财方案+支撑依据和解释（确保用户信任）
2、agent负责回答用户问题，提供进一步解释和说明，并结合用户反馈提供修改
## 3、后馈
总结当月消费情况：
提供结果反馈，详细展示本月的开销情况、方案执行情况，产品效果（攒了多少钱）
调整分配的模型算法：
agent总结经验，更新用户画像

## 实现方案
web app
接入agent：
1、模型：DeepSeek V4.1 flash
2、框架：交互agent直接手搓，方案agent给ai自主选择
**交互agent：**提示词：定义交流风格、交流流程、终止条件（需要达成怎样的信息收集程度）；与用户多轮对话，直到判定满足终止条件，输出结构化的用户画像报告
**方案agent：**skill+tool（可能涉及workflow），实现网络信息收集+结构化方案输出+支撑依据
