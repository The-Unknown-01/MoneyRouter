# 月份主流程

主流程：**核对 M 月完整账单 → 确认 M 月整月复盘 → 核对 M+1 月预计资料 → 生成并确认 M+1 月方案**。

例如在 2026-10，默认导入 2026-09 账单，复盘九月后制定十月方案。相对月份始终以明确的 YYYY-MM 为锚点，跨年同样适用。

## 数据与入口

| 页面 / 数据 | 月份 | 含义 |
|---|---|---|
| `/ledger`、`/month` | M | 已发生实际收入、支出、储蓄和投资执行；需核对整月完整性 |
| `/review` | M | 与 M 月原方案比较；无原方案也可以分析收支并复盘 |
| `/forecast` | M+1 | 用户确认的预计整月总收入、待支付固定费用 / 最低还款 / 特殊支出、已知环境与明确允许动用的余额 |
| `/plan` | M+1 | 将 M 月账单、复盘、画像与 M+1 月预期组合后，由 Agent 提案、独立校验、用户确认 |
| `/month` → `/plan?mode=adjustment` | 当前月 | 核对当前实际执行后，调整已有方案；与下一月主流程分别保存会话 |

预计资料保存为 `forecast_result`，不写入实际月度历史。历史支出只作为预算参考，不复制为方案月份已花；历史收入不复制为方案月份已到账。预计收入必须明确填值，0 是有效值。应急储蓄不会自动作为可花资金。

## 状态与校验

1. 确认月度资料不等于月末结账。只有已结束自然月、明确整月完整、无待复核流水且实际收入已知，才可进入正式整月复盘。
2. 下一月预计资料的依据必须是紧邻 M 月的完整账单与已确认整月复盘。缺月不能用更早记录替代。
3. 预计资料先整理为待确认卡片，再显式确认。输入版本、来源账单或复盘变化后，重新核对；已更新的账单须重新复盘。
4. 生成方案时再次检查预计资料版本与来源，防止绕过页面直接提交。方案 `input_facts` 保存 `planning_mode`、`source_period` 和生成时依据。
5. 历史方案只回看。不能为已经过去的月份新增执行安排。当月中途使用执行跟踪与调整入口，整月结束后再复盘并规划下一月。

历史复盘数据若缺少新流程的账单依据信息，需要重新生成并确认复盘后进入下一月规划，原记录与方案仍保留。

## 验证

自动测试覆盖预计与实际分开、相邻月份、完整复盘门槛、0 收入、来源账单更新后的拒绝、预计资料版本失效、主流程和当月调整的独立会话，以及结构化字符串数组契约和长会话工具消息完整性。Python 全量 536 项通过，Go 全量与 go vet 通过。
