## 修复与优化

1. **按用途分类**：移除支付宝“转账红包”和微信“转账 / 微信红包 / 群收款 → 人情往来”的强制映射。人情往来要求明确礼金、随礼等用途。AA、代付按实际消费用途分类；用途未知则保留其他。
2. **防止模型凭姓名猜用途**：没有商品说明的转账类支出，即便模型猜出类别也由代码收回为其他；缺少明确礼赠用途时不接受模型的人情往来判定。人工纠正可覆盖此限制。
3. **消除二次猜测**：未知类别明确写其他，并生成复核原因，防止下游再次按备注或姓名误分类。去除单字规则命中，例如“界面科技”不再因“面”字被归到餐饮。
4. **关闭思考与减少重复调用**：原程序已有默认关闭开关，本轮验证其覆盖全局思考配置，分类温度设置为 0。相同来源、商家、商品、平台类目、交易类型在一次清洗中复用分类。仅对选定月份调用模型。
5. **严格校验分类响应**：模型编号缺失、重复、越界时拒绝整批结果并回退规则；每批失败不影响其他批。重试次数与输出预算遵循项目配置。
6. **缩小模型输入**：模型请求仅含用途相关文字和批内编号，金额、日期、交易编号不发送给模型。文字用 JSON 编码，提示词明确忽略账单字段中的指令。
7. **支持复核与纠正**：输出保留来源、原始行号、交易编号、分类来源及复核原因；额外生成 `review.json`。新增 `--category-overrides`，人工分类优先于模型。
8. **修复解析细节**：保留零金额记录用于笔数核对；校验真实日期，拒绝错位 CSV 列；补齐 XLSX 上传字节流的汇总读取；声明 openpyxl 依赖。无效参数在分类调用前拒绝，CLI 对损坏文件返回错误码而非异常堆栈。
9. **纠正退款说明**：删除“退款转为不计收支等于净额口径”的结论。保留默认平台方向，退款相关记录进入复核清单；兼容的 transfer 选项明确标注跨月、部分退款及缺失原单风险。

## 使用与证据

程序入口：`agent/scripts/clean_bill.py`，文件内容接口：`clean(alipay=csv_bytes, wechat=xlsx_bytes)`。

```powershell
# 默认真实分类，思考模式关闭
./.venv/Scripts/python.exe scripts/clean_bill.py --alipay "支付宝交易明细.csv" --wechat "微信账单.xlsx" --out cleaned

# 使用人工纠正；键为 来源:交易编号，值为项目固定消费类目
./.venv/Scripts/python.exe scripts/clean_bill.py --wechat "微信账单.xlsx" --category-overrides corrections.json --out corrected
```

纠正文件示例：`{"wechat:交易编号": "居住"}`。缺少编号时可以使用 `wechat:row:原始行号`，支付宝同理。有效类别沿用项目十类体系，非法类别拒绝处理。

## 后续仍需处理

- 上传界面应先展示待复核清单，让用户补充用途，再确认月度实况；本轮只优化现有清洗后端与 CLI，未新增 Go 网页上传页面。
- 七月、十月只覆盖本次导出的部分月份，月度输出不代表完整自然月，不能直接当作完整月环比基线。
- 当前原样保留平台退款方向。若要财务净消费口径，应另做原订单关联、部分退款及跨月分摊，不能简单删除退款行。
- 转账入账、退款入账不等于工资或稳定收入；资金流汇总不能直接写入用户的稳定月收入画像。
- 相同交易编号的重复上传还需要上传层的导入记录去重；跨平台疑似重复继续只提示，不能仅按时间和金额删交易。
