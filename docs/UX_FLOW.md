# 单线程界面修改方案

## 用户路径

`注册/登录 → AI 画像访谈与用户确认 → 手填或导入账本 → 本月实况核对与确认 → 方案生成/修改/确认 → 可选复盘或答疑`

当前页面采用 HTMX 主内容替换与任务轮询；财务 HTML 不保存于本地历史缓存。输入更新后须重新核对本月事实，再更新方案。手机编辑账单采用底部弹层，桌面定位编辑表单；图表显示确认的事实与规则结果，缺失数据保持空白。规范账单 JSON/CSV、支付宝 CSV、微信 XLSX 均先清洗预览，点击确认才写入账本。Python 无密钥或超时沿用其规则降级，不调用 Go 旧模型与算法。

- `/` 按账号数据跳转到当前步骤；不再渲染仪表盘。
- 顶部仅有三个进度标记和当前账号。进度标记不承担全局跳转，避免让用户跳过尚未完成的步骤。
- 画像页先呈现 Agent 对话，再呈现可编辑画像。用户核对确认后进入账本；模型不可用时可直接填写。
- 账本页的手填和 CSV 为同一步骤的两个录入选项。至少一笔记录后提供方案入口；模拟账单只进入当前账号且不覆盖画像。
- 方案页按月收入流向、预备金、可配置资金、Agent 解释的顺序阅读。复盘和答疑在方案后提供可选入口，返回方案即可继续。
- 已完成的用户可以从方案回到账本补录，也可回到画像修改。重新生成方案时保留版本记录。

## 路由约束与验收

- 未确认画像时，账本及之后的业务路由返回画像步骤。
- 已确认画像但账本为空时，方案及可选分支返回账本步骤。
- 未保存方案时，复盘和答疑返回方案步骤。
- 直接访问 `/` 与登录后的跳转一致；两个账号按各自进度独立跳转。
- 桌面与手机宽度均为单列主内容；无侧栏、底部全局导航或仪表盘卡片矩阵。
- 功能回归覆盖画像、CSV 预览与确认、手填编辑、方案生成、复盘、答疑和跨账号隔离。

## 动效约定

- 每次进入步骤或可选分支时，主内容短距离淡入；离开页面时轻微淡出。登录、注册、筛选和返回操作沿用同一节奏。
- 画像问答、账单保存/导入、方案生成/重算、复盘筛选与答疑均有可见的操作反馈；等待模型或导入时显示不宣称具体完成百分比的进度动画。
- 表单编辑定位、账本录入方式展开、方案资金分配逐项呈现有局部过渡。动效使用透明度与位移，避免大面积复杂计算。
- 遵循 `prefers-reduced-motion`；关闭动效时流程和反馈文字仍完整可用。
